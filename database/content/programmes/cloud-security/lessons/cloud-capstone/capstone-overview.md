## The capstone scenario

A fictional regional logistics company has moved its customer portal to the cloud. You are asked to review the architecture before an investor's due-diligence audit.

## What you will do

1. **Review the architecture**: networks, public exposure, data stores and administrative access.
2. **Identify IAM risks**: over-privileged roles, long-lived keys and escalation paths.
3. **Identify configuration risks** against a baseline.
4. **Analyse supplied audit logs** for signs of misuse.
5. **Recommend controls and remediation**, prioritised by exposure, privilege and data sensitivity.
6. **Write a cloud security assessment report.**

## How it is assessed

The IAM review and audit-log analysis are validated automatically in labs. The written report is self-assessed against a checklist, giving you an artefact you can discuss with employers (with the fictional scenario clearly labelled).

## Report checklist

- [ ] Architecture summary and data-flow description
- [ ] Shared-responsibility assumptions stated
- [ ] IAM findings with least-privilege alternatives
- [ ] Configuration findings mapped to a named baseline and version
- [ ] Audit-log findings with evidence references
- [ ] Prioritised remediation roadmap with owners
- [ ] Backup and recovery assessment

## Ground rules

Essential capstone activities use supplied data only, so no paid cloud resources are required. Never test cloud accounts or resources you do not own or have explicit permission to assess.
